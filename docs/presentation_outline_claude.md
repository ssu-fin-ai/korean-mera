## 2. 관련 연구 (Related Work) — 4분

### 2.1 원 논문: MERA (WWW 2025)
- Mixture of Experts with Retrieval-Augmented Representation
- 핵심 아이디어: 패턴 다양성 → 전문가 분리 + RAG로 유사 사례 참조
- 원 논문과 본 구현의 차이점 (GPU 없이 LLM API 대체, 한국 시장 데이터)

### 2.2 RAG (Retrieval-Augmented Generation)
- 벡터 유사도 검색 기반 컨텍스트 주입
- 금융 도메인에서의 RAG: 유사 과거 패턴 → 현재 의사결정 보조

### 2.3 MoE (Mixture of Experts) in Finance
- 시장 국면별 전문가 분리의 이론적 근거
- LLM Agent 기반 MoE vs. 전통적 앙상블 모델

### 2.4 LLM Agent 시스템
- Tool-use / Multi-agent 구조
- GateNet (라우터) + Expert Agents 패턴

### 2.5 원 논문(MERA)과 본 구현의 차이점

| 항목 | 원 논문 (MERA, WWW 2025) | Korean-MERA (본 구현) |
|------|--------------------------|----------------------|
| **모델 구조** | GPU 기반 MoE 신경망 (noisy gate + expert layer) | Claude LLM API 기반 에이전트 |
| **임베딩** | Self-supervised pre-training (학습된 수치 벡터) | OpenAI text-embedding-3-small (자연어 텍스트) |
| **RAG 구성** | 오프라인 사전계산 similars50.h5 (50개 고정) | 실시간 ChromaDB 코사인 검색 (Top-5) |
| **입력 데이터** | 가격·기술지표 수치만 (뉴스·재무 없음) | 기술지표 + 재무지표(PER/PBR/ROE) + DART 공시 |
| **전문가 라우팅** | GateNet → 1~2개 전문가 선택 | 전문가 5개 동시 병렬 실행 (fan-out) |
| **대상 시장** | CSI300(중국), S&P500(미국) | KOSPI200(한국) |
| **샘플링 단위** | 일별 (daily) | 월별 (월말 기준, API 비용 절감) |
| **인프라** | GPU 서버 필수 | API 호출만으로 동작 |

**보존된 핵심 아이디어:**
- MoE 구조: 패턴 유형별 전문가 분리 + confidence 기반 집계
- RAG 구조: 유사 과거 패턴 검색 → 현재 의사결정 보조

**본 구현의 추가 기여:**
- 재무·공시 데이터 통합으로 원 논문보다 풍부한 컨텍스트 제공
- GPU 없이 LLM API만으로 유사 아키텍처 구현 가능성 입증
- 한국 시장 특화 데이터 파이프라인 (pykrx, 네이버 금융, DART)
- **RAG → Confidence 직접 연동**: 과거 유사 패턴 적중률·평균수익이 전문가 confidence를 조정 → 원 논문의 익명 전문가 가중치를 해석 가능한 방식으로 구현

## 3. 시스템 아키텍처 (System Architecture) — 5분

### 3.1 전체 파이프라인

```
데이터 수집 → 피처 엔지니어링 → 텍스트 생성
     → 임베딩 → ChromaDB (RAG)
     → Screener (후보 종목 선별)
     → 전문가 에이전트 × 5 (병렬 fan-out, 전원 동시 실행)
     → 집계 (Aggregator) → 포트폴리오 → 평가
```

### 3.2 데이터 수집 모듈
- OHLCV: pykrx (주말·공휴일 실패) → FinanceDataReader 자동 fallback
- 재무 지표: 네이버 금융 API (PER, PBR, EPS, BPS, 배당수익률)
- 공시: DART API (최근 30일 공시 제목)
- 대상: KOSPI200 (~200 종목)

### 3.3 피처 엔지니어링

| 구분 | 지표 |
|------|------|
| 모멘텀 | RSI-14, MACD diff, 5일/20일 수익률 |
| 추세 | ADX, MA20/MA60 대비 |
| 변동성 | 볼린저밴드 %B, 역사적 변동성 20일 |
| 수급 | MFI-14, 거래량 비율 |
| 상대 | KOSPI 대비 상대강도 |
| 재무 | Forward PER, Trailing PER, PBR, 배당수익률 |

## 4. RAG 모듈 — 4분

### 4.1 패턴 텍스트 생성
- 기술적 + 재무 지표 → 자연어 텍스트 변환 (`text_generator.py`)
- 예시:

```
종목: 005930 삼성전자 | 시장: KOSPI | 섹터: 전기전자
수익률: 5일+3.2% 20일+8.5%
추세: 강한상승추세 | MA20대비5.2% MA60대비8.1%
RSI: 65(강세) | MACD: 골든크로스/상승세
볼린저: 상단대(0.72) | 거래량: 급증(2배+)
역사적변동성(20일): 18.3% | ADX: 28 | MFI: 62
```

### 4.2 RAG DB 저장 구조

ChromaDB에 저장되는 1건의 구성:

| 필드 | 내용 | 예시 |
|------|------|------|
| **ID** | `{ticker}_{날짜}` | `005930_2024-03-15` |
| **Text** | 기술지표 자연어 패턴 (임베딩 대상) | RSI, MACD, 거래량, 수익률 등 |
| **Embedding** | 1,536차원 벡터 | OpenAI text-embedding-3-small |
| **label_5d** | 5거래일 후 실제 수익률 | `+0.032` |
| **label_10d** | 10거래일 후 실제 수익률 | `+0.051` |
| **label_20d** | 20거래일 후 실제 수익률 | `+0.078` |
| **ticker** | 종목코드 | `005930` |
| **name** | 종목명 | `삼성전자` |
| **sector** | 섹터 | `반도체` |
| **market** | 시장 | `KOSPI` |
| **date** | 기준일 | `2024-03-15` |

### 4.3 임베딩 및 벡터 저장소 구축
- OpenAI `text-embedding-3-small` (1,536차원)
- ChromaDB: KOSPI200 × 3년 일별 샘플링 = **약 150,000건** 패턴
- 유사도: 코사인 유사도, Top-k=5 검색

### 4.3 검색 메커니즘 (Retrieval)
- 현재 패턴 → 임베딩 → 유사 과거 5개 패턴 + 당시 실제 수익률 반환
- 전문가 에이전트 프롬프트에 아래 형태로 주입:

```
[유사 과거 패턴 (RAG)]
  1. 유사도:94% → 5일후:+3.2%
  2. 유사도:91% → 5일후:-1.1%
  3. 유사도:88% → 5일후:+5.4%
  4. 유사도:85% → 5일후:+6.7%
  5. 유사도:83% → 5일후:+1.8%
  적중률:4/5 | 평균수익:+3.2%
```

### 4.4 RAG → Confidence 연동 (핵심 설계)
- 전문가는 펀더멘털 분석을 **주 판단 기준**으로 사용
- RAG 적중률·평균수익을 **confidence 조정 근거**로 활용:
  - 적중률 4/5 이상 + 평균수익 플러스 → confidence 상향
  - 적중률 2/5 이하 또는 평균수익 마이너스 → confidence 하향 or HOLD
- RAG만으로 BUY하지 않도록 명시적 제약

**장점:**
- 라우팅 미스매치 없음 — 모든 전문가가 동일하게 RAG 활용
- 실증 데이터 기반 — "이 패턴에서 과거 80% 플러스" 가 직접 신호
- 해석 가능 — 왜 confidence가 높은지 RAG 근거로 설명 가능

## 5. AI Agent 시스템 (Multi-Agent) — 6분

### 5.1 병렬 Fan-out 구조

원 논문의 GateNet(단일 전문가 라우팅) 대신 **모든 전문가를 동시에 실행**하는 구조를 채택했다.

```
Screener → ┌── growth   ──┐
            ├── value    ──┤
            ├── theme    ──┼──→ Aggregator → Portfolio
            ├── dividend ──┤
            └── crisis   ──┘
            (LangGraph 병렬 fan-out)
```

**GateNet 라우팅 대비 장점:**
- 라우팅 오류로 인한 전문가 누락 없음
- 동일 종목을 여러 관점에서 동시 평가 → 다양한 신호 확보
- 신뢰도(confidence) 기반 집계로 자연스러운 전문가 가중치 결정

### 5.2 5개 전문가 에이전트

| 에이전트 | 선택 조건 | 핵심 판단 기준 |
|----------|-----------|---------------|
| growth | RSI 60+, MACD 골든크로스, 거래량↑ | Forward PER, 컨센서스 EPS |
| value | 저PBR, 저변동성, MA 하단 횡보 | PBR < 1, 배당수익률 3%+ |
| theme | 거래량 3배+, 공시 이슈, 단기 급등 | 테마 사이클 위치, 수급 과열도 |
| dividend | 저변동성, 방어 섹터 (통신·유틸) | 배당수익률 4%+, 이익 안정성 |
| crisis | 5일 수익률 -10↓, RSI 과매도 30- | 급락 원인 (일시적 vs 구조적) |

### 5.3 에이전트 출력 구조

```json
{
  "ticker": "005930",
  "name": "삼성전자",
  "signal": "BUY",
  "confidence": 0.85,
  "target_return": 0.10,
  "horizon_days": 10,
  "score": 8,
  "reason": "핵심 투자 근거 (2~3문장)",
  "pros": ["긍정 요인1", "긍정 요인2"],
  "cons": ["리스크 요인1"]
}
```

### 5.4 포트폴리오 집계 (Aggregator)
- 신뢰도 필터: confidence ≥ 0.60
- TOP-N 선정: 최대 20종목 (전문가당 5종목 기준)
- ThreadPoolExecutor 병렬 처리: 200종목 약 7분

## 6. 실험 및 검증 (Evaluation) — 5분

### 6.1 백테스트 방법론
- 보유기간: 당월 첫 거래일 → 당월 마지막 거래일 (월간 리밸런싱)
- 평가 범위: 2025년 1~12월 (월별), 2026년 (연간)
- 신호 생성일: 각 월 첫 거래일 / 청산일: 동일 월 마지막 거래일

### 6.2 성과 지표 정의

| 지표 | 산식 | 의미 |
|------|------|------|
| ARR | 누적수익^(252/보유일수) - 1 | 연환산 수익률 |
| MDD | min((누적 - 고점) / 고점) | 최대 낙폭 |
| Sharpe | 평균수익 / 표준편차 × √(252/보유일) | 단위 리스크당 수익 |
| Sortino | 평균수익 / 하방표준편차 × √(252/보유일) | 하방 리스크 조정 수익 |
| Calmar | ARR / \|MDD\| | 낙폭 대비 연수익 |

### 6.3 결과 요약
> *(발표 시 실제 백테스트 수치 삽입)*

- 2025년 월별 적중률, ARR, MDD 추이
- KOSPI200 벤치마크 대비 초과 수익 분석
- 전문가별 기여도 (어떤 에이전트가 가장 많이 선택되었는가)

- Prompt Caching 적용으로 API 비용 최대 50% 절감

## 9. 결론 (Conclusion) — 1분

- MERA 논문의 핵심 아이디어(MoE + RAG)를 GPU 없이 LLM API로 재현 가능함을 입증
- GateNet + 5 전문가 에이전트 구조가 다양한 시장 국면에 적응적으로 대응
- 한국 주식시장에 특화된 데이터 파이프라인(pykrx, 네이버 금융, DART) 구축
- 백테스트로 검증된 실용적 AI 투자 에이전트 시스템

# 발표자 정리본 검토 첨언

> 대상 파일: `01_발표목차.md`, `02_예상질문지.md`, `03_발표스크립트.md`  
> 기준 자료: 최신 코드 기준 정리본 `03_논문에서_한국형_MERA로_발표정리본_원작자자료반영.md`, 원작자 `코드_문서_불일치_검토보고서.md`  
> 추가 확인 자료: 원작자 흐름도 `01_DB구축_흐름도.png`, `02_종목선정_흐름도.png`, `03_종목평가_흐름도.png`  
> 목적: 발표자가 개발자가 아니어도 발표 중 코드 구조와 다른 표현으로 질문을 받지 않도록, 수정이 필요한 부분과 설명 보강 방향을 정리한다.

---

## 1. 총평

세 파일의 큰 흐름은 좋다.

```text
문제의식
→ 원본 MERA 논문
→ 한국형 MERA 재해석
→ 시스템 설계
→ 백테스트 결과
→ 한계와 향후 과제
```

이 서사는 유지해도 된다. 특히 “논문을 그대로 복제한 것이 아니라, Retrieval + MoE 아이디어를 한국 시장용 LLM 투자 분석 시스템으로 재해석했다”는 방향은 발표 전체의 중심 문장으로 적절하다.

다만 최신 코드와 원작자 검토보고서 기준으로 보면 몇 군데는 반드시 조정하는 편이 좋다.

```text
1. Gate 설명: Gate가 빠진 것처럼 보이면 안 됨
2. Top-20 표현: 현재 최종 통합 포트폴리오는 Top-5 기준
3. Expert 출력: risks가 아니라 pros/cons, 단일 종목이 아니라 picks 배열
4. RAG와 confidence: 수식으로 직접 보정이 아니라 Expert prompt에 판단 근거로 제공
5. 성과 수치: 큰 누적 수치 사용 시 산식·기간·벤치마크·거래비용 한계를 같이 설명
6. 비개발자 발표: embedding, Gate, Aggregator 같은 용어는 처음 나올 때 쉬운 풀이 필요
```

## 2. 원작자 흐름도 기준 추가 검토

세 장의 원작자 흐름도는 발표자료에서 그대로 근거 이미지로 쓰기 좋다. 다만 발표자가 이미지 내용을 잘못 읽으면 코드와 어긋난 설명이 나올 수 있으므로, 아래 기준으로 설명하는 것이 안전하다.

### 2-1. `01_DB구축_흐름도.png`: 과거 유사패턴 DB 구축

이미지 핵심 흐름:

```text
KOSPI200 전체 종목
→ OHLCV 수집
→ 기술지표 계산
→ Snapshot + label 생성
→ 패턴텍스트 + Embedding
→ ChromaDB 저장
```

발표에서 강조할 점:

```text
이 단계는 매일 종목을 고르는 단계가 아니라,
현재 종목을 분석할 때 참고할 과거 사례 DB를 미리 만드는 단계입니다.
```

비개발자용 설명:

```text
사람이 과거 차트를 보고 "이전에도 비슷한 흐름이 있었나?"를 떠올리는 것처럼,
시스템은 KOSPI200의 과거 거래일 패턴을 미리 저장해 둡니다.
이 저장소가 이후 RAG 검색의 기억장치 역할을 합니다.
```

이미지에서 발표에 반영해야 할 정확한 표현:

| 이미지 항목 | 발표 표현 |
|---|---|
| KOSPI200 약 200종목 | 분석 대상은 대표 대형주 중심 |
| pykrx primary, FDR fallback | 국내 데이터 수집 실패 시 대체 경로 사용 |
| RSI, MACD, Bollinger Band, ADX, MFI, MA, 변동성 | 가격 자체가 아니라 기술지표 상태를 패턴화 |
| label_5d, label_10d, label_20d | 과거 패턴 이후 실제 수익률 |
| 공시 미포함 | RAG 임베딩에는 공시가 항상 들어가지 않음 |
| OpenAI text-embedding-3-small, 1,536차원 | 패턴 텍스트를 검색 가능한 숫자 벡터로 변환 |
| ChromaDB `stock_patterns` | 과거 유사패턴 검색용 저장소 |

주의할 표현:

```text
"공시까지 포함해서 과거 패턴을 embedding한다"라고 말하면 안 됩니다.
이미지에도 "공시 미포함"이라고 명시되어 있고,
현재 정리 기준에서도 공시는 Expert 분석 맥락으로 전달되는 정보입니다.
```

### 2-2. `02_종목선정_흐름도.png`: 일별 종목 선정

이 이미지는 발표자료에서 가장 중요하다. 최신 코드 구조와 원작자 검토보고서의 핵심 수정 사항이 거의 모두 들어 있다.

이미지 상단의 실제 실행 흐름:

```text
START → screener → gate → [5 Expert 병렬] → aggregator → reporter → END
```

발표에서 반드시 지켜야 할 설명:

```text
Screener 다음에 Gate가 있습니다.
5개 Expert가 바로 실행되는 것이 아니라,
Gate가 먼저 종목별 전문가 가중치를 계산합니다.
```

단계별 설명:

```text
1. Screener 내부 ①
   OHLCV, 기술지표, 재무, DART 공시, 공매도, 52주 위치, 섹터 정보를 수집합니다.

2. Screener 내부 ②
   현재 종목 패턴텍스트를 만들고 ChromaDB에서 유사 과거패턴을 검색합니다.
   유사 과거패턴의 label 수익률을 확인해 RAG 통계를 Expert prompt에 전달합니다.

3. Screener 내부 ③
   growth/value/theme/dividend/crisis 관점별 휴리스틱 스코어를 계산하고,
   각 전문가별 Top-15 후보군을 만듭니다.

4. Gate 노드
   후보 종목별로 5개 전문가 각각의 적합도를 0.0~1.0 가중치로 계산합니다.

5. 5개 Expert 병렬 분석
   각 Expert는 Top-15 후보를 받아 최대 5개 picks를 선택합니다.

6. Aggregator
   전문가별 picks를 합치고,
   Gate weight × confidence × score 기반으로 combined Top-5를 만듭니다.
```

이미지 기준으로 꼭 맞춰야 할 표현:

| 항목 | 이미지 기준 | 발표자료 수정 방향 |
|---|---|---|
| 후보 수 | 전문가별 Top-15 후보 | “KOSPI200 전체를 LLM이 보는 것이 아니라 후보를 압축한다” |
| Expert 출력 | 각 Expert 최대 5 picks | “각 Expert가 최대 5개 추천 종목을 고른다” |
| 전문가별 포트폴리오 | 각 최대 5개 | “전문가별 포트폴리오와 통합 포트폴리오를 따로 저장” |
| 통합 포트폴리오 | combined_portfolio 5개 | `Top-20`이 아니라 `combined Top-5` |
| Gate | `gate_weights_map` | “전문가 선택”이 아니라 “전문가별 가중치” |
| Aggregator 점수 | Gate 가중치 × confidence × score | 단순 평균이 아니라 가중 통합 |
| RAG 활용 | Expert prompt 첨부 → confidence 조정 | 수식 보정이 아니라 판단 근거 제공 |

비개발자용 설명:

```text
이 그림은 투자위원회처럼 이해하면 쉽습니다.
Screener가 회의에 올릴 후보 종목을 고르고,
Gate가 각 종목에 대해 어떤 전문가 의견이 더 중요한지 비중을 정합니다.
그 뒤 성장·가치·테마·배당·위기 전문가가 동시에 검토하고,
Aggregator가 최종 5개 종목으로 포트폴리오를 정리합니다.
```

발표자료에서 수정하면 좋은 곳:

```text
01_발표목차.md S11:
스크리너→전문가→어그리게이터→평가
→ Screener(RAG 포함) → Gate → 5 Expert 병렬 → Aggregator → 평가

03_발표스크립트.md S11:
"스크리너가 후보를 추리고, 5개 전문가가 병렬 분석하고..."
→ "스크리너가 후보를 추리고 RAG 결과를 붙인 뒤, Gate가 전문가별 가중치를 계산합니다.
그다음 5개 전문가가 병렬 분석하고 Aggregator가 최종 Top-5로 통합합니다."
```

### 2-3. `03_종목평가_흐름도.png`: 종목 평가

이미지 핵심 흐름:

```text
평가 대상 선정
→ 실제 수익률 계산
→ AI 투자 판단 검토
→ 성과 지표 계산
→ 결과 기록 저장
```

발표에서 강조할 점:

```text
한국형 MERA는 추천만 하고 끝나는 시스템이 아니라,
추천한 종목이 실제로 수익을 냈는지 월별/주별로 다시 평가합니다.
```

이미지 기준 평가 대상:

```text
전문가별 포트폴리오 5개 × 5명
+ 통합 포트폴리오 5개
= 최대 30개 종목
```

이미지 기준 평가 방식:

```text
월별: 월초 선정 → 월말 평가
주별: 월요일 선정 → 5영업일 후 평가
```

이미지 기준 성과 지표:

```text
적중률
연환산 수익률(ARR)
최대 낙폭(MDD)
Sortino 비율
Calmar 비율
```

중요:

```text
이미지에는 Sharpe가 없습니다.
따라서 발표자료나 스크립트에서 Sharpe를 넣지 않는 것이 안전합니다.
```

비개발자용 설명:

```text
AI가 고른 종목을 실제로 샀다고 가정하고,
선정 시점 가격과 평가 시점 가격을 비교해 수익률을 계산합니다.
그리고 수익률뿐 아니라 최대 낙폭과 하방 위험까지 함께 봅니다.
```

발표자료에서 수정하면 좋은 곳:

```text
01_발표목차.md S15:
평가지표는 적중률·ARR·MDD·Sortino·Calmar로 유지
Sharpe는 추가하지 않기

03_발표스크립트.md S15:
"위험 조정 성과"라고 말할 때,
Sortino와 Calmar가 어떤 의미인지 짧게 풀어주면 좋음
```

## 3. 최우선 수정 사항

### 3-1. Gate 설명을 최신 구조에 맞추기

현재 발표자료에는 다음 식의 설명이 있다.

```text
원본 GateNet 라우팅은 스크리너 + 병렬 전문가 + 어그리게이터로 재구성
```

이 설명은 큰 방향은 맞지만, 구현체에는 실제 `Gate` 노드가 존재한다. 따라서 “Gate가 없다”거나 “Screener 다음 바로 5개 전문가가 분석한다”처럼 들리면 코드와 어긋난다.

최신 기준의 정확한 흐름:

```text
Screener(RAG 검색 포함)
→ Gate
→ 5개 Expert 병렬 분석
→ Aggregator
→ Reporter / 평가
```

비개발자용 설명:

```text
Screener는 종목 후보를 줄이는 1차 필터입니다.
Gate는 후보 종목마다 성장·가치·테마·배당·위기 관점이 각각 얼마나 중요한지 가중치를 매깁니다.
5개 Expert는 각자 관점으로 후보를 분석합니다.
Aggregator는 전문가 추천 결과와 Gate 가중치를 합쳐 최종 포트폴리오를 만듭니다.
```

추천 수정 문장:

```text
원본 MERA의 GateNet은 한국형 구현에서 하나의 딥러닝 라우터로 그대로 복제된 것이 아니라,
Screener, Gate weight, 5개 Expert 병렬 분석, Aggregator로 나뉘어 재해석되었습니다.
```

적용 위치:

- `01_발표목차.md`: S7, S8, S11
- `02_예상질문지.md`: Q4
- `03_발표스크립트.md`: S7, S11

특히 `02_예상질문지.md` Q4는 아래처럼 바꾸는 것이 좋다.

```text
원본 GateNet은 입력 샘플에 적합한 expert를 고르는 딥러닝 라우터입니다.
한국형 MERA에서는 이 역할이 하나의 모듈로만 대응되지 않고,
Screener → Gate weight → 5개 Expert 병렬 분석 → Aggregator로 나뉘어 구현됩니다.
구현체의 Gate는 growth, value, theme, dividend, crisis 5개 관점 각각에 0.0~1.0 가중치를 부여하고,
Aggregator가 이 가중치를 최종 점수에 반영합니다.
```

### 3-2. Top-20 표현을 Top-5 기준으로 수정

현재 파일에 남아 있는 문제 표현:

```text
confidence 0.6 이상 BUY만 모아 신뢰도 가중으로 Top-20을 만듭니다.
```

최신 코드 기준:

```text
각 Expert는 최대 5개 picks를 생성
Aggregator는 BUY + confidence 0.60 이상 후보를 모음
Gate weight, confidence, score를 반영
최종 combined_portfolio는 Top-5
```

왜 중요한가:

```text
Top-20이라고 말하면 최종 포트폴리오가 20개 종목으로 구성되는 것처럼 들린다.
하지만 현재 settings.yaml의 portfolio.top_n은 5이고, 통합 포트폴리오는 Top-5가 맞다.
```

추천 수정 문장:

```text
Aggregator는 confidence 0.60 이상인 BUY picks를 모은 뒤,
Gate weight, confidence, score를 반영해 최종 combined Top-5 포트폴리오를 구성합니다.
```

적용 위치:

- `01_발표목차.md`: S15
- `03_발표스크립트.md`: S15
- 암기 카드의 “4단계” 설명에도 `어그리게이터 → Top-5`를 명시하면 좋음

### 3-3. Expert 출력 형식: `risks`가 아니라 `pros/cons`

현재 발표자료에는 다음 표현이 있다.

```text
JSON 출력(signal/confidence/target_return/risks/reason)
```

최신 코드 기준 출력은 다음 구조다.

```json
{
  "picks": [
    {
      "ticker": "005930",
      "name": "종목명",
      "signal": "BUY",
      "confidence": 0.85,
      "target_return": 0.10,
      "horizon_days": 10,
      "score": 8,
      "reason": "핵심 투자 근거",
      "pros": ["긍정 요인1", "긍정 요인2"],
      "cons": ["리스크 요인1", "리스크 요인2"]
    }
  ]
}
```

비개발자용 핵심:

```text
Expert는 종목 하나만 분석하는 것이 아니라,
후보군 전체를 보고 최대 5개 추천 종목 목록(picks)을 만든다.
각 추천 종목에는 매수/보유/매도 판단, 신뢰도, 목표수익률, 근거, 긍정 요인, 주의 요인이 들어간다.
```

추천 수정 문장:

```text
각 Expert는 후보군 중 최대 5개 picks를 JSON으로 출력합니다.
각 pick에는 signal, confidence, target_return, score, reason, pros, cons가 포함됩니다.
```

적용 위치:

- `01_발표목차.md`: S14
- `03_발표스크립트.md`: S14

### 3-4. RAG와 confidence 표현을 조심스럽게 수정

현재 표현:

```text
RAG 결과로 confidence를 올리고 내린다.
```

이 표현은 큰 방향은 맞지만, 코드상 confidence가 별도 수식으로 자동 보정되는 것은 아니다. RAG 통계가 Expert prompt에 들어가고, LLM이 그 정보를 참고해 confidence를 판단한다.

추천 수정 문장:

```text
RAG로 찾은 과거 유사 패턴의 적중률과 평균수익률은 Expert prompt에 포함됩니다.
LLM Expert는 이 정보를 참고해 confidence를 높이거나 낮추도록 지시받습니다.
즉 RAG는 자동 결정 규칙이 아니라 과거 사례 기반의 판단 보조 근거입니다.
```

적용 위치:

- `01_발표목차.md`: S13
- `02_예상질문지.md`: Q6, Q18
- `03_발표스크립트.md`: S13

## 5. 비개발자 발표자가 특히 조심할 용어

아래 용어는 그대로 써도 되지만, 처음 등장할 때 쉬운 설명을 붙이는 것이 좋다.

| 용어 | 쉬운 설명 |
|---|---|
| RAG | 현재 종목과 비슷했던 과거 사례를 찾아 참고하는 방식 |
| embedding | 텍스트나 패턴을 검색 가능한 숫자 벡터로 바꾸는 것 |
| ChromaDB | 비슷한 벡터를 빠르게 찾기 위한 검색 DB |
| Gate | 어떤 전문가 관점이 중요한지 가중치를 주는 장치 |
| Expert | 성장·가치·테마·배당·위기 관점으로 분석하는 LLM 역할 |
| Aggregator | 여러 전문가 추천을 모아 최종 포트폴리오로 합치는 장치 |
| confidence | AI가 제시한 판단 신뢰도 |
| picks | Expert가 고른 추천 종목 목록 |
| pros/cons | 긍정 요인 / 주의 요인 |
| label | 과거 패턴 이후 실제 수익률 |
| universe | 분석 대상 종목군 |
| regime | 시장 국면 |
| slippage | 주문 가격과 실제 체결 가격 차이 |
| benchmark | 비교 기준 지수나 전략 |

발표자가 개발자가 아니라면, 용어를 많이 줄이기보다 “처음 한 번 쉽게 번역”하는 것이 더 좋다. 그래야 코드/논문 용어를 유지하면서도 청중이 따라올 수 있다.

```text
이 파이프라인이 과거 데이터에서 어떤 신호를 냈는지 확인하는 검증용 참고 자료입니다.
```

## 7. 최종 체크리스트

발표 전 아래 항목을 고치면 코드와 문서의 불일치 위험이 크게 줄어든다.

- [ ] `Top-20` 표현을 `combined Top-5`로 수정
- [ ] `risks` 표현을 `pros/cons` 또는 `긍정 요인/주의 요인`으로 수정
- [ ] GateNet 설명에 실제 `Gate weight` 존재를 포함
- [ ] 전체 흐름을 `Screener(RAG 포함) → Gate → 5 Expert → Aggregator`로 설명
- [ ] RAG가 confidence를 직접 수식 보정한다고 단정하지 않기
- [ ] 공시가 RAG embedding에 항상 포함된다고 말하지 않기
- [ ] 평가지표에 `Sharpe`를 넣지 않고 `Calmar`를 포함
- [ ] 성과 수치는 산식, 기간, 벤치마크, 거래비용 한계를 함께 언급
- [ ] “원본보다 성능이 좋다” 대신 “설명 가능성과 한국 시장 적용성을 높였다”로 표현
- [ ] 비개발자 청중을 위해 `RAG`, `embedding`, `Gate`, `Aggregator`, `confidence`는 첫 등장 시 쉬운 말로 풀이

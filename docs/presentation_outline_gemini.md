## 1. 서론

### 1.1 연구 동기

주식 시장에서 수익을 내는 AI 시스템을 만드는 일은 단순히 좋은 예측 모델을 만드는 것이 아니다.  
**"어떤 종목이 어떤 이유로 오르는가"** 는 국면마다 전혀 다른 논리를 따른다.

- 금리 인상기에는 배당주가 채권과 경쟁하고
- 정책 발표 직후에는 테마주가 수급을 독식하며
- 실적 시즌에는 성장주의 컨센서스가 주가를 결정한다

**단일 모델로 모든 국면을 설명하려는 시도는 구조적으로 한계가 있다.**

### 1.2 연구 목적

본 프로젝트는 WWW 2025에 발표된 MERA 논문의 핵심 아이디어를 한국 주식시장에 적용한다.

- 원 논문의 MoE(Mixture of Experts) + RAG 구조를 LLM API 기반으로 재구현
- GPU 없이 Anthropic Claude + OpenAI 임베딩만으로 동작하는 실용 시스템 구축
- 2025년 12개월 월별 백테스트로 시스템 성능을 **정량적으로 검증**

### 1.3 기여 요약

| 기여 | 내용 |
|------|------|
| 한국 시장 적용 | KOSPI200 대상, 한국 재무/공시 데이터 파이프라인 구축 |
| LLM 기반 MoE | GateNet + 5 전문가 에이전트로 원 논문 구조 재현 |
| RAG 검색 | ChromaDB + OpenAI 임베딩으로 유사 과거 패턴 참조 |
| 정량 검증 | 2025년 12개월 월별 백테스트 (ARR / MDD / Sortino / Calmar) |

## 2. 배경 및 관련 연구

### 2.1 원 논문: MERA (WWW 2025)

**Mixture of Experts with Retrieval-Augmented Representation for Modeling Diversified Stock Patterns**

| 항목 | 내용 |
|------|------|
| 핵심 문제 | 주식 패턴의 다양성 → 단일 모델 부적합 |
| 핵심 해법 | 패턴 유형별 전문가 분리 (MoE) + 유사 사례 검색 (RAG) |
| 검증 방식 | CSI300, S&P500 백테스트 |
| 한계 | GPU 필요, 영문 데이터 기반 |

**본 프로젝트와의 차이점:**

```
원 논문                          Korean-MERA
─────────────────────────────────────────────
딥러닝 기반 전문가 라우팅     →  Claude LLM 기반 GateNet
중국/미국 시장                →  한국 KOSPI200
사전학습 임베딩 모델          →  OpenAI text-embedding-3-small
GPU 필요                      →  API 호출만으로 동작
```

### 2.2 RAG (Retrieval-Augmented Generation)

- 모델이 알지 못하는 외부 정보를 검색하여 프롬프트에 주입
- 금융 적용: **과거 유사 주가 패턴 → 당시 실제 수익률**을 현재 판단에 활용
- 핵심 질문: *"이 패턴, 예전에도 있었나? 그때 어떻게 됐나?"*

### 2.3 Mixture of Experts (MoE)

- 입력 특성에 따라 적합한 전문가 모듈을 선택하는 앙상블 구조
- 전통적 MoE: 소프트맥스 게이팅 네트워크
- 본 프로젝트: **Claude LLM이 게이팅** 역할 수행 (GateNet)

### 2.4 LLM Multi-Agent 시스템

- 단일 LLM 호출의 한계: 복잡한 판단을 하나의 프롬프트에 담기 어려움
- 역할 분리: 라우터(GateNet) → 전문가(Expert Agents) → 집계(Aggregator)
- 각 에이전트는 자신의 도메인에 최적화된 프롬프트와 판단 기준 보유

## 3. 문제 정의

### 3.1 한국 주식시장의 특수성

일반적인 주식 예측 모델이 한국 시장에서 실패하는 이유:

- **테마 민감도**: 정책 발표 하루 만에 관련주 20~30% 급등/급락
- **공시 의존성**: DART 공시가 주가에 즉각 반영
- **재무 지표 해석**: 동일한 PBR도 섹터마다 정상 범위가 다름
- **수급 구조**: 개인 투자자 비중이 높아 기술적 지표가 중요

### 3.2 핵심 과제

```
[입력] 200종목의 현재 상태
       ├── 기술적 지표 (RSI, MACD, BB, ADX, MFI 등)
       ├── 재무 지표 (PER, PBR, EPS, 배당수익률 등)
       └── 공시/뉴스 (DART 최근 30일)

[목표] 어떤 종목을 언제 사고팔아야 하는가?
       └── BUY / HOLD / SELL 신호 + 신뢰도 + 목표 수익률
```

### 3.3 왜 단일 모델로는 부족한가

| 국면 | 성장주 접근 | 위기주 접근 |
|------|------------|------------|
| RSI 70, 거래량 3배 | 모멘텀 추종 → BUY | 과열 경고 → HOLD |
| PBR 0.5, 저변동 | 가치 미반영 → HOLD | 자산 안전마진 → BUY |

**같은 데이터도 투자 철학에 따라 반대 결론** → 전문가 분리 필수

## 4. 시스템 설계

### 4.1 전체 아키텍처

```
┌─────────────────────────────────────────────────────────┐
│  데이터 수집                                              │
│  pykrx / FinanceDataReader / 네이버 금융 / DART          │
└──────────────────────┬──────────────────────────────────┘
                       │ OHLCV + 재무 + 공시
┌──────────────────────▼──────────────────────────────────┐
│  피처 엔지니어링                                          │
│  RSI · MACD · BB · ADX · MFI · 거래량비율 · 상대강도     │
└──────────────────────┬──────────────────────────────────┘
                       │ 패턴 텍스트 생성
┌──────────────────────▼──────────────────────────────────┐
│  RAG 레이어                                               │
│  OpenAI 임베딩(1536d) → ChromaDB → 유사패턴 Top-5 검색   │
└──────────────────────┬──────────────────────────────────┘
                       │ 현재패턴 + 유사과거사례
┌──────────────────────▼──────────────────────────────────┐
│  GateNet (Claude)                                         │
│  전문가 라우팅: growth / value / theme / dividend / crisis│
└──────────────────────┬──────────────────────────────────┘
                       │ 전문가 선택 결과
┌──────────────────────▼──────────────────────────────────┐
│  Expert Agents × 5 (Claude)                              │
│  각 전문가: BUY/HOLD/SELL + confidence + target_return   │
└──────────────────────┬──────────────────────────────────┘
                       │ 신호 집계
┌──────────────────────▼──────────────────────────────────┐
│  Aggregator → 포트폴리오 (TOP-20, confidence ≥ 0.60)    │
└──────────────────────┬──────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────────┐
│  Evaluator → ARR / MDD / Sortino / Calmar                │
└─────────────────────────────────────────────────────────┘
```

### 4.2 데이터 파이프라인

| 소스 | 데이터 | 갱신 | 용도 |
|------|--------|------|------|
| pykrx / FDR | OHLCV | 일별 캐시 | 기술적 지표 계산 |
| 네이버 금융 API | PER·PBR·EPS·BPS·배당수익률·컨센서스 | 월별 캐시 | 재무 에이전트 입력 |
| DART API | 최근 30일 공시 제목 | 실시간 (선택) | 테마·위기 에이전트 |
| pykrx | KOSPI 지수 OHLCV | 일별 | 상대강도 계산 |

## 5. RAG 파이프라인

### 5.1 패턴 텍스트 생성

수치 데이터를 자연어로 변환하여 의미 기반 유사도 검색 가능하게 함:

```
종목: 005930 삼성전자 | 시장: KOSPI | 섹터: 전기전자
수익률: 5일+3.2% 20일+8.5%
추세: 강한상승추세 | MA20대비5.2% MA60대비8.1%
RSI: 65(강세) | MACD: 골든크로스/상승세
볼린저: 상단대(0.72) | 거래량: 급증(2배+)
역사적변동성(20일): 18.3% | ADX: 28 | MFI: 62
```

### 5.2 벡터 저장소 구축

- **임베딩 모델**: OpenAI `text-embedding-3-small` (1,536차원)
- **저장소**: ChromaDB (로컬, GPU 불필요)
- **규모**: KOSPI200 × 3년 월말 샘플링 = **5,972건**
- **구축 비용**: ~$0.03 (최초 1회)

### 5.3 유사 패턴 검색 및 활용

```
[현재 패턴] → 임베딩 → 코사인 유사도 검색
                             ↓
              [유사 과거 사례 Top-5]
              ├── 사례1: 유사도 0.94 | 이후 5일: +8.2%
              ├── 사례2: 유사도 0.91 | 이후 5일: +5.1%
              ├── 사례3: 유사도 0.88 | 이후 5일: -2.3%
              ├── 사례4: 유사도 0.85 | 이후 5일: +6.7%
              └── 사례5: 유사도 0.83 | 이후 5일: +3.4%
                             ↓
              GateNet / Expert 프롬프트에 주입
              → "과거 유사 패턴 5개 중 4개가 플러스 수익"
```

**RAG의 역할**: LLM이 알지 못하는 *이 종목의 과거 선례*를 실시간으로 제공

## 6. Multi-Agent 시스템

### 6.1 GateNet — 전문가 라우터

모든 종목은 GateNet을 먼저 통과한다.

**입력:**
- 현재 종목 패턴 텍스트
- ChromaDB에서 검색한 유사 과거 5사례

**출력:**
```json
{
  "experts": ["growth"],
  "confidence": 0.82,
  "pattern_type": "실적모멘텀 성장주",
  "reason": "RSI 65로 강세, 거래량 2배 급증, 20일 수익률 +12%"
}
```

### 6.2 5개 전문가 에이전트

#### growth — 성장주 전문가
- **선택 조건**: RSI 60+, MACD 골든크로스, 거래량 증가, 20일 수익률 플러스
- **핵심 판단**: Forward PER vs Trailing PER, 컨센서스 EPS 상향 여부
- **BUY 기준**: 포워드PER 낮음 + 컨센서스EPS 상향 + 모멘텀 강함

#### value — 가치주 전문가
- **선택 조건**: 저PBR, 낮은 변동성, MA 하단 횡보
- **핵심 판단**: PBR 1 미만 여부, 배당수익률 3%+, 촉매 이벤트 존재 여부
- **BUY 기준**: PBR < 1 + 배당 3%+ + 이익 안정 + 자사주 매입 등 촉매

#### theme — 테마주 전문가
- **선택 조건**: 거래량 3배+, 공시 이슈, 볼린저 상단 돌파
- **핵심 판단**: 테마 사이클 위치 (초기/중기/말기), 정책 직접 수혜 여부
- **BUY 기준**: 테마 초기 + 직접 수혜 + 거래량 급증

#### dividend — 배당주 전문가
- **선택 조건**: 저변동성, 방어 섹터 (통신·유틸리티·금융)
- **핵심 판단**: 배당수익률 4%+, 이익 대비 배당성향, 금리 환경
- **BUY 기준**: 배당수익률 4%+ + 이익 안정 + 저변동성

#### crisis — 위기종목 전문가
- **선택 조건**: 5일 수익률 -10% 이하, RSI 과매도(30-), 볼린저 하단
- **핵심 판단**: 급락 원인이 일시적인가 구조적인가
- **BUY 기준**: 일시적 악재 + MFI 과매도 + 유사패턴 반등 사례 다수

### 6.3 에이전트 출력 구조

```json
{
  "ticker": "005930",
  "signal": "BUY",
  "confidence": 0.85,
  "target_return": 0.10,
  "horizon_days": 10,
  "score": 8,
  "reason": "2~3문장 투자 근거",
  "pros": ["수치 포함 긍정 요인1", "수치 포함 긍정 요인2"],
  "cons": ["수치 포함 리스크 요인1"]
}
```

### 6.4 포트폴리오 집계

- 신뢰도 필터: `confidence ≥ 0.60`
- 최종 선정: TOP-20종목 (전문가당 최대 5종목)
- 병렬 처리: ThreadPoolExecutor (workers=10) → **200종목 약 7분**

## 7. 실험 설계 및 검증

### 7.1 백테스트 구조

```
[신호 생성] 각 월 첫 거래일 → MERA 시스템으로 포트폴리오 선정
                ↓
[보유 기간] 월초 종가 매수 → 월말 종가 청산
                ↓
[수익률 계산] (월말종가 - 월초종가) / 월초종가
                ↓
[성과 집계] ARR / MDD / Sharpe / Sortino / Calmar
```

### 7.3 평가 지표

| 지표 | 산식 | 의미 |
|------|------|------|
| 적중률 (Hit Rate) | 수익 신호 수 / 전체 BUY 신호 수 | 방향 예측 정확도 |
| 평균 수익률 | 보유기간 수익률 평균 | 개별 신호 평균 성과 |
| ARR | 누적수익^(252/보유일) - 1 | 연환산 수익률 |
| MDD | min((누적 - 고점) / 고점) | 최대 낙폭 |
| Sharpe | 평균수익 / 표준편차 × √(252/보유일) | 단위 리스크당 수익 |
| Sortino | 평균수익 / 하방표준편차 × √(252/보유일) | 손실 구간만 반영 |
| Calmar | ARR / \|MDD\| | 낙폭 대비 연수익 |

### 7.4 비교 기준 (Baseline)
- KOSPI200 인덱스 수익률 (Buy & Hold)
- 전문가 없는 단순 신뢰도 필터 포트폴리오

## 9. 한계 및 향후 연구

### 9.1 현재 한계

| 한계 | 원인 | 영향 |
|------|------|------|
| LLM 할루시네이션 | Claude가 수치를 잘못 해석 가능 | 신호 오류 |
| 거래 비용 미반영 | 슬리피지·수수료 미포함 | 실제 수익률 과대 추정 |
| 월간 리밸런싱 고정 | 시장 급변 시 대응 불가 | 위기 대응 지연 |
| RAG DB 정적 | 신규 패턴 자동 학습 없음 | 시장 구조 변화 적응 한계 |
| 유니버스 제한 | KOSPI200만 대상 | 코스닥 고성장주 제외 |

### 9.2 향후 연구 방향

- **온라인 학습**: 매일 새 패턴을 ChromaDB에 자동 추가하여 DB 진화
- **Prompt Caching**: Anthropic 캐시 API 적용으로 비용 최대 50% 절감
- **코스닥 확장**: 유니버스를 KOSPI200 + KOSDAQ150으로 확대
- **거래 비용 모델**: 슬리피지·수수료·세금 반영한 현실적 백테스트
- **강화학습 통합**: 포트폴리오 비중 최적화에 RL 에이전트 도입

## 10. 결론

### 핵심 메시지

> MERA 논문의 핵심 아이디어인 **"패턴 다양성에 맞는 전문가 분리 + 과거 유사 사례 참조"** 는

3. **검증**: 2025년 12개월 월별 백테스트로 시스템 성능을 정량 측정
4. **실용성**: 200종목을 7분 내 처리하는 일별 운용 가능 시스템
